# 게임 UI 온톨로지

단일 화면으로 판별 가능한 화면 요소 간 관계 오류를 규칙으로 정의하고, 규칙에서 개념·관계를 도출

- 구성 요소: **① 규칙 + ② 개념 계층 + ③ 관계 + ④ 게임별 매핑**

*※ 이탤릭은 모두 예시*

### ① 규칙

상황 열거가 아닌, 화면 요소가 항상 만족해야 하는 관계로 작성. 규칙마다 성립 전제를 명시하고, 타 게임 적용 여부는 장르가 아닌 전제 공유 여부로 판단

- **공통 규칙**: 전제(화면에서 확인할 수 있는 게임의 성질)를 만족하는 모든 게임에 적용
    - *캐릭터는 단단한 지형과 상당 부분 겹쳐서는 안 됨 (배경 장식·통과 발판은 제외)*
        - *전제: 캐릭터와 지형이 한 화면에 함께 보이고, 통과 가능한 지형이 구분되는 게임*
    - *값 표시는 반드시 어떤 대상을 나타내야 함 (대상 없는 체력바 = 위반)*
        - *전제: 값 표시가 대상 근처에 배치되고, 표시 하나가 대상 하나에 대응하는 게임 (화면 상단 고정 UI·파티 통합 표시는 별도 규칙 필요)*
- **게임별 규칙**: 전제로 판단할 수 없는 기획 의도를 반영. 해당 게임 설정(④)에서 켬

### ② 개념 계층

성질별 축으로 분리된 여러 트리

- 화면 요소는 각 축의 노드 조합으로 표현
    - *의미: 무엇을 나타내는가 (예: 값 표시 ⊃ 체력 표시)*
    - *형태: 어떻게 그려지는가. 라벨링 클래스의 기준*
    - *배치: 월드 위치를 따라가는가, 화면에 고정되는가*

- 규칙마다 걸리는 축이 다르므로, 축 분리로 규칙이 특정 형태에 묶이지 않게 함
- 상위 개념은 넓게, 게임별 구현은 말단에서 흡수
- 코어와 게임군별 모듈로 구분. 경계는 규칙 축적 후 조정

### ③ 관계

규칙에서 역으로 도출, 단순 기하 계산이라 게임 종류와 무관하게 사용됨

- **계산 관계**: 마스크에서 자동 산출. 온톨로지는 정의만 보유, 계산은 추론 라이브러리 담당
    - *겹침(overlaps): 캐릭터와 지형의 겹침 정도*
    - *가림(occludes): UI가 대상을 덮는 정도*
    - *근접(nearBy): 체력 표시와 대상 캐릭터를 짝짓기 위해 필요*
- **라벨링 관계**: 사람이 지정
    - *나타냄(represents): 이 체력바는 저 보스를 나타냄*

### ④ 게임별 매핑

사용자가 작성하는 게임별 설정. 규칙은 상위 개념에 걸려 있어 매핑만으로 적용

- 화면 요소 → 개념 연결 *(예: 하트 아이콘 = 체력 표시)*
- 게임별 규칙 켜기
- 임계값 등 파라미터 조정


### ※ 확장 원칙
- 뼈대(①~④): 장르 무관
- 내용(개념·규칙): 실사례 근거가 있는 것만 추가
- 노드: 규칙·매핑에서 쓰이는 것만
- 상위 개념: 복수 사례가 같은 관계를 요구할 때 생성


## 도출 절차

사례 하나씩 반복하며 내용 추가

```
사례 → 판별 가능 확인 → ① 규칙 → 반례 검토 → ② 개념 계층 → ③ 관계 → ④ 게임별 매핑
```

1. 사례 수집: 버그 사례(위반 화면)
2. 판별 가능 확인: 단일 화면 판별, 요소 간 관계 오류 여부. 채택·제외 사유 기록
3. ① 규칙: 기존 규칙으로 설명되면 근거 사례로만 추가. 아니면 관계·전제·위반 명칭을 갖춘 새 규칙 작성
4. 반례 검토: 정상 화면이 위반으로 걸리는 경우 처리
    - 개념 분리, 전제 보완, 조건 축소
    - 전제로 판단 불가 시 게임별 규칙으로 전환
5. ② 개념 계층: 규칙이 참조하는 개념을 축별 계층에 위치 지정. 기존 노드 재사용 우선
6. ③ 관계: 규칙 판정에 필요한 관계 정의. 기존 관계 재사용 우선, 계산·라벨링 구분
7. ④ 게임별 매핑: 게임별 연결 개념, 게임별 규칙, 조정 파라미터 기록

주기적 정리: 미사용 노드 제거, 상위 개념화 검토, 코어·모듈 경계 조정
