# 게임 UI 온톨로지

단일 화면으로 판별 가능한 화면 요소 간 관계 오류를 규칙으로 정의하고, 규칙에서 개념·관계를 도출

- 구성 요소: **① 규칙 + ② 개념 계층 + ③ 관계 + ④ 게임별 매핑**

*※ 이탤릭은 모두 예시*

### ① 규칙

상황 열거가 아닌, 화면 요소가 항상 만족해야 하는 관계로 작성. 규칙마다 성립 전제를 명시하고, 타 게임 적용 여부는 장르가 아닌 전제 공유 여부로 판단

- **공통 규칙**: 전제(객관적으로 판단 가능한 게임의 성질)를 만족하는 모든 게임에 적용
    - *고정 오브젝트는 아래쪽이 지형과 접촉함*
        - *전제: 측면 시점이고 중력 방향이 화면 아래쪽인 게임*
    - *월드 표시는 나타내는 대상을 가짐 (대상 없는 체력바 = 위반)*
        - *전제: 표시 하나가 대상 하나에 대응하는 게임*
- **게임별 규칙**: 전제로 판단할 수 없는 기획 의도를 반영. 해당 게임 설정(④)에서 켬

### ② 개념 계층

성질별 축으로 분리된 여러 트리

- 화면 요소는 각 축의 노드 조합으로 표현
    - *역할: 무엇인가 (표시 ⊃ 체력 표시)*
    - *배치: 월드 위치를 따라가는가, 화면에 고정되는가*
- 축은 규칙이 요구하는 구분에서 도출
- 규칙마다 걸리는 축이 다르므로, 축 분리로 규칙이 특정 성질 조합에 묶이지 않게 함
- 라벨링 클래스는 규칙이 구분해야 하는 축 값의 조합

### ③ 관계

규칙에서 역으로 도출. 온톨로지는 정의만 보유, 계산은 추론 라이브러리 담당

- **측정값**: 마스크에서 계산하는 수치. 기하 계산이라 게임 종류와 무관. 규칙은 측정값에 임계값을 적용해 판정
    - *겹침 비율(overlap_ratio): 대상 중 지형과 겹치는 면적 비율*
    - *거리(distance): 체력 표시와 대상 개체 사이 거리*
- **관계**: 인스턴스 사이의 참·거짓. 학습 데이터에서 사람이 지정하거나 계산, 판정 시에는 계산 또는 매핑으로 결정
    - *나타냄(represents): 이 체력바는 저 보스를 나타냄*

### ④ 게임별 매핑

사용자가 작성하는 게임별 설정. 규칙은 상위 개념에 걸려 있어 매핑만으로 적용

- 게임 성질(전제) 선언
- 화면 요소 → 개념 연결 *(하트 아이콘 = 체력 표시)*
- 게임별 규칙 켜기
- 임계값 등 파라미터 조정


### ※ 확장 원칙
- 뼈대(①~④): 장르 무관
- 내용(규칙·개념·관계): 실사례 근거가 있는 것만 추가
- 노드: 규칙·매핑에서 쓰이는 것만. 제외 대상은 노드가 아닌 정의의 제외 기준으로 기록
- 상위 개념: 여러 하위 개념이 같은 규칙에 걸릴 때 생성
- 전제: 대상 개념이 있으면 자명한 조건, 개념 정의로 표현되는 조건은 제외
- 정본: 규칙 파일이 개념·관계·측정값·전제·임계값 참조의 정본. 역방향 색인을 두지 않음
- 도입 근거: 개념이 처음 필요해진 규칙·반례만 기록하고 고정
- ID: 규칙·전제는 추가 순서대로 순번, 삭제된 ID는 재사용 금지. 라벨링 클래스 ID는 변경·재사용 금지
- 원본 데이터: 수정하지 않음
- 온톨로지 파일: md와 겹치는 정의는 함께 수정. 관계 결정 근거, 측정값 상세 정의는 md에만


## 도출 절차

사례 하나씩 반복하며 내용 추가

```
사례 → 판별 가능 확인 → ① 규칙 → 반례 검토 → ② 개념 계층 → ③ 관계 → ④ 게임별 매핑
```

1. 사례 수집: 버그 사례(설명 또는 화면). 설명 사례는 화면 확인 전까지 미검증
2. 판별 가능 확인: 단일 화면 판별, 요소 간 관계 오류 여부. 채택·제외 사유 기록
3. ① 규칙: 기존 규칙으로 설명되면 근거 사례로 추가 후 7단계로. 아니면 관계·측정값·전제·위반 명칭·임계값을 갖춘 새 규칙 작성
4. 반례 검토: 정상 화면에 규칙을 적용해 위반으로 걸리는 경우 처리
    - 개념 분리, 전제 보완, 조건 축소, 임계값 조정, 관계·측정값 보완
    - 전제로 판단 불가 시 게임별 규칙으로 전환
    - 처리 기준은 1_rules/README.md
5. ② 개념 계층: 규칙이 참조하는 개념을 축별 계층에 위치 지정. 기존 노드 재사용 우선, 필요한 구분이 기존 축에 없으면 축 추가
6. ③ 관계: 규칙 판정에 필요한 관계·측정값 정의. 기존 것 재사용 우선
7. ④ 게임별 매핑: 전제 해당 여부, 연결 개념, 게임별 규칙, 조정 파라미터 기록

주기적 정리: 미사용 노드 제거, 상위 개념화 검토

## 파일 구성

```
ontology/
├── README.md        설계 원칙, 도출 절차, 파일 구성
├── 0_cases/         [절차 1, 2] 사례
│   ├── README.md    출처 목록, 인용 형식, 판별 기준, 제외 사유
│   └── <출처>/       출처별 원본 데이터와 분석
├── 1_rules/         [절차 3, 4] 규칙
│   ├── README.md    규칙 목록, 전제 목록, 임계값 목록, 반례 처리 기준
│   └── <규칙 ID>.md  규칙별 상세, 근거 사례, 반례
├── 2_concepts.md    [절차 5] 축, 개념 정의, 조합 개념·라벨링 클래스
├── 3_relations.md   [절차 6] 관계, 측정값
├── game_ui.ttl      [절차 5, 6] 온톨로지 파일 (OWL). 개념, 라벨링 클래스, 관계, 측정값 정의
├── rules.ttl        [절차 3, 4] 규칙 SHACL 형상 (SHACL-SPARQL). 형상마다 읽는 파라미터·측정값 선언. 파라미터 값은 검증 시 데이터로 추가
├── tests/           md와 온톨로지 파일 정의 일치 테스트
└── mappings/        [절차 7] 게임별 매핑. 첫 매핑 작성 시 생성
```
