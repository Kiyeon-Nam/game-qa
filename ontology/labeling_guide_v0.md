# 클래스 목록 v0 및 라벨링 가이드

> **대상**: 라벨링 참여자 전원
> **근거 문서**: `3_concepts.md`(개념 계층), `4_relations.md`(관계 정의)
> **라벨 형식**: COCO instance segmentation + `relations` 필드
> **변경 원칙**: 클래스 추가·병합 결정 시 이 문서의 버전을 올린다. 라벨링 중 애매한 사례는 임의로 정하지 말고 10장의 방식으로 기록한다.

## 1. 클래스 목록

| ID | 클래스 | 한 줄 정의 | 관련 규칙 |
|---|---|---|---|
| 0 | Character | 플레이어, 적, NPC 등 움직이는 생명체 | R-PHY-01, R-RND-01, R-ATT-01 |
| 1 | LooseObject | 고정되지 않은 작은 개체 (아이템, 코인, 투사체, 던진 무기) | R-PHY-02 |

## 2. 공통 규칙

**2-1. 보이는 부분만 칠한다**
가려진 부분은 칠하지 않는다. 캐릭터가 전경 풀숲 뒤에 반쯤 가려져 있으면 보이는 절반만 칠한다. 모델도 보이는 부분만 예측하므로 정답도 같은 기준이어야 한다.
- 예외: UI는 2-3 참고

**2-2. 인스턴스 단위**
- 개체(클래스 0~3, 7)는 **하나의 개체 = 하나의 인스턴스**
- 여러 마디로 된 한 개체(벌레형 적, 꼬리가 분리된 보스)는 **한 인스턴스**로 칠한다. 떨어져 있는 조각이면 폴리곤을 여러 개 그려 같은 인스턴스로 묶는다.
- 지형(4)은 **연결된 덩어리 하나 = 하나의 인스턴스**. 화면에서 떨어져 있는 지형 덩어리는 별도 인스턴스
- 발판(5)은 **발판 한 조각 = 하나의 인스턴스**

**2-3. UI는 겹쳐서 칠한다**
UI 요소 안에 다른 UI가 들어 있으면 **바깥 요소를 안쪽 요소까지 포함한 전체 영역으로 칠하고, 안쪽 요소를 한 번 더 칠한다.** 포함 관계(R-UI-01, 02)를 계산하려면 바깥 요소의 전체 영역이 필요하기 때문이다.
- 예: 체력바 HUD 위에 "80/100" 숫자 → `HUDElement`는 숫자 영역까지 포함한 사각형 전체, `TextLabel`은 숫자만
- 예: 대화창 안의 대사 → `UIPanel`은 상자 전체, `TextLabel`은 글자 덩어리

**2-4. 경계 정밀도**
- 개체·UI는 외곽선을 따라 픽셀 단위로 칠한다. 경계에서 2~3px 정도 차이는 허용
- 지형은 블록 격자를 따라 칠한다 (타일 경계에 맞춤)
- 너무 작아서 무엇인지 판별할 수 없는 것(대략 가로·세로 4px 미만)은 칠하지 않는다

**2-5. 화면 경계에 걸친 것**
화면 밖으로 일부 나간 개체도 보이는 부분은 칠한다.

## 3. 월드 개체 클래스

### 0. Character
| 포함 | 제외 |
|---|---|
| 플레이어, 적, NPC, 보스, 펫·소환수 | 배경 그림 속 인물 (→ 칠하지 않음) |
| 캐릭터가 입은 옷·갑옷·모자·망토 | 손에 든 무기·도구 (→ 2 Equipment) |
| 탈것에 탄 상태의 캐릭터 + 탈것 (한 인스턴스) | 캐릭터 이름표, 체력바 (→ 7 HealthBar 등) |
| | 공격 이펙트, 잔상 (→ 칠하지 않음) |

### 1. LooseObject
| 포함 | 제외 |
|---|---|
| 바닥에 떨어진 아이템, 코인, 보석, 하트 픽업 | 손에 들고 있는 무기 (→ 2 Equipment) |
| 날아가는 화살, 총알, 마법탄, 던진 무기 | 상자, 문 등 고정물 (→ 3 GroundedObject) |
| 바닥에 떨어진 무기 | 빛나는 파티클, 반짝임 효과 (→ 칠하지 않음) |

### 2. Equipment
| 포함 | 제외 |
|---|---|
| 캐릭터 손에 붙어 있는 무기, 도구, 방패 | 손을 떠난 무기 (→ 1 LooseObject) |
| 등에 멘 무기 중 캐릭터와 분리돼 보이는 것 | 몸에 입은 갑옷·옷 (→ 0 Character) |
| | 휘두를 때의 궤적·잔상 (→ 칠하지 않음) |

**판단 기준**: 같은 스프라이트(예: 부메랑)라도 **손에 붙어 있으면 Equipment, 손을 떠났으면 LooseObject, 바닥에 있으면 LooseObject**.
**관계 태깅 필수**: Equipment마다 들고 있는 Character와 `attachedTo` 관계를 태깅한다.

### 3. GroundedObject
| 포함 | 제외 |
|---|---|
| 상자, 보물상자, 문, 가구, 표지판, 항아리 | 벽에 걸린 횃불·액자, 천장 샹들리에 (→ 칠하지 않음) |
| 바닥에 서 있는 동상, 기계 장치 | 줍는 아이템 (→ 1 LooseObject) |
| | 블록처럼 밟을 수 있는 상자 (→ 4 Terrain) |

**판단 기준**: **바닥에 놓여 있어야 정상인 물체**만 해당. 벽·천장에 붙는 물체는 넣지 않는다 (R-PHY-03 오탐 방지).

## 4. 월드 구조 클래스

### 4. Terrain
| 포함 | 제외 |
|---|---|
| 밟을 수 있는 바닥 블록, 막히는 벽, 천장 | 배경 벽, 원경 산·건물 (→ 칠하지 않음) |
| 경사로, 계단 블록 | 아래에서 통과 가능한 얇은 발판 (→ 5 Platform) |
| 움직이는 고체 블록 | 물, 용암 (→ 칠하지 않음) |
| | 캐릭터 앞에 그려지는 장식 (→ 6 ForegroundDecoration) |

**판단 기준**: **캐릭터가 부딪히는가**. 같은 색·질감이라도 뒤쪽 배경 벽(캐릭터가 그 앞을 지나다님)이면 Terrain이 아니다. 판단이 어려우면 게임을 직접 플레이하거나 영상에서 캐릭터가 지나가는 장면을 확인한다.
**주의**: 캐릭터가 지형 앞에 서 있어 지형이 가려진 부분은 **칠하지 않는다** (2-1). 가려진 지형 추정은 후처리에서 한다.

### 5. Platform
| 포함 | 제외 |
|---|---|
| 아래에서 점프해 뚫고 올라갈 수 있는 발판 | 사방이 막힌 고체 발판 (→ 4 Terrain) |
| 나무 발판, 구름 발판, 얇은 다리 | 줄·사다리 (→ 칠하지 않음) |

**판단 기준**: **아래에서 통과 가능한가**. 확인이 어려우면 두께가 얇고 아래가 비어 있는 발판을 Platform으로 본다.

### 6. ForegroundDecoration
| 포함 | 제외 |
|---|---|
| 캐릭터를 가리며 앞에 그려지는 풀숲, 덩굴, 기둥, 창살 | 캐릭터 뒤에 그려지는 장식 (→ 칠하지 않음) |
| 동굴 입구 등 전경 레이어 구조물 | 날씨 효과(비·눈), 안개 (→ 칠하지 않음) |

**판단 기준**: **캐릭터가 그 뒤로 지나가는가**. 캐릭터가 앞을 지나가면 배경이므로 칠하지 않는다.

## 5. UI 클래스

### 7. HealthBar
| 포함 | 제외 |
|---|---|
| 적·캐릭터 머리 위나 근처에 붙어 다니는 체력바 (테두리 포함 전체) | 화면에 고정된 플레이어 체력 HUD (→ 8 HUDElement) |
| | 화면 상단에 고정된 보스 체력바 (→ 8 HUDElement) |

**판단 기준**: **개체를 따라 움직이면 HealthBar, 화면에 고정돼 있으면 HUDElement**.
**관계 태깅 필수**: HealthBar마다 그것이 나타내는 Character와 `represents` 관계를 태깅한다. 체력바만 있고 대상이 화면에 없으면 태깅하지 않는다 (이 경우가 바로 버그 B01).
**v0 미포함**: 이름표, 조준 표시는 v0에서 칠하지 않는다. 대상 게임에 자주 나오면 이슈로 등록해 클래스 추가를 결정한다.

### 8. HUDElement
| 포함 | 제외 |
|---|---|
| 체력 하트·체력 게이지, 점수, 목숨 수, 미니맵, 아이템 슬롯, 버튼 아이콘 | 대화창·메뉴 창·툴팁 (→ 9 UIPanel) |
| 화면 상단 보스 체력바 | HUD 안의 숫자·글자는 따로 한 번 더 (→ 10 TextLabel) |

**인스턴스 단위**: **기능 하나 = 인스턴스 하나**. 하트 5개가 나란히 있으면 하트 줄 전체가 하나의 HUDElement. 점수 영역과 목숨 영역은 별도 인스턴스.
**역할(체력, 점수 등)은 칠하지 않는다**. 역할은 게임 매핑에서 정한다.

### 9. UIPanel
| 포함 | 제외 |
|---|---|
| 대화창, 메뉴 창, 설정 창, 툴팁, 알림 팝업 (상자 전체) | 상자 없이 화면에 바로 뜨는 글자 (→ 10 TextLabel만) |
| | HUD 구성 요소 (→ 8 HUDElement) |

### 10. TextLabel
| 포함 | 제외 |
|---|---|
| UI 패널·HUD 안의 글자, 화면에 바로 뜨는 안내 문구 | 개체를 따라다니는 데미지 숫자 (→ 칠하지 않음) |
| | 게임 세계 안 표지판에 그려진 글자 (→ 3 GroundedObject의 일부) |
| | 로고·그림 문자 (→ 소속 UI의 일부) |

**인스턴스 단위**: **한 줄 또는 한 덩어리 = 인스턴스 하나**. 대화창의 대사 3줄이 한 문단이면 하나로 칠한다. 화자 이름과 대사처럼 떨어져 있으면 별도.
**잘린 글자**: 패널 경계에서 잘린 글자도 보이는 부분만 칠한다 (버그 B07의 정답 데이터가 됨).

## 6. 관계 태깅

| 관계 | 방향 | 언제 태깅하나 |
|---|---|---|
| represents | HealthBar → Character | 모든 HealthBar. 대상이 화면에 없으면 태깅하지 않음 |
| attachedTo | Equipment → Character | 모든 Equipment |

나머지 관계(겹침, 포함, 지지, 가림)는 마스크에서 자동 계산하므로 태깅하지 않는다.

라벨 JSON의 `relations` 필드 예시:
```json
"relations": [
  {"type": "represents", "subject": 12, "object": 3},
  {"type": "attachedTo", "subject": 15, "object": 3}
]
```
`subject`, `object`는 같은 이미지 안의 annotation id.

## 7. 자주 헷갈리는 경우

| 상황 | 처리 |
|---|---|
| 보스 체력바가 화면 상단에 고정 | HUDElement (HealthBar 아님) |
| 상자를 밟고 올라갈 수 있음 | 블록처럼 쌓인 지형 상자면 Terrain, 열 수 있는 보물상자면 GroundedObject |
| 캐릭터가 전경 풀숲 뒤에 반쯤 가려짐 | Character는 보이는 부분만, 풀숲은 ForegroundDecoration |
| 캐릭터가 문 앞에 서 있음 | 문은 GroundedObject, 캐릭터는 보이는 부분만 |
| 캐릭터가 사망 연출 중 반투명 | 형태가 보이면 Character로 칠함 |
| 아이템이 공중에 떠서 흔들림 | LooseObject (정상 동작) |
| 화살이 벽에 꽂혀 있음 | LooseObject (보이는 부분만) |
| 탈것(말, 슬라임)에 탄 캐릭터 | 캐릭터와 탈것을 합쳐 Character 한 인스턴스 |
| HUD 아이콘 위의 수량 숫자 | 아이콘은 HUDElement(숫자 포함 영역), 숫자는 TextLabel로 한 번 더 |
| 일시정지 메뉴가 화면 전체를 덮음 | 메뉴 창은 UIPanel, 그 아래 게임 화면은 보이는 만큼 칠함 |

## 8. 라벨링 전 확인 (게임마다 1회)

새 게임을 라벨링하기 전에 아래를 확인해 `data/<게임>/notes.md`에 적는다.

- 이 게임의 Terrain과 배경 벽은 어떻게 구분되는가 (색, 밝기, 테두리)
- Platform이 있는가, 어떻게 생겼는가
- ForegroundDecoration 레이어가 있는가
- HealthBar가 개체를 따라다니는가, 화면에 고정인가
- v0 클래스에 없는 요소가 자주 나오는가 (이름표, 조준 표시 등)

## 9. 품질 기준

- 라벨링을 시작할 때 각자 **같은 이미지 10장**을 칠한 뒤 서로 비교해 기준을 맞춘다
- 전체 라벨의 약 5%는 다른 사람이 검수한다
- 클래스를 잘못 고른 경우가 마스크 경계 오차보다 훨씬 치명적이다. 경계를 정밀하게 칠하는 것보다 클래스 판단을 우선한다

---

## 10. 애매한 경우 기록 방법

이 가이드로 판단할 수 없는 사례는 다음처럼 처리한다.

1. 일단 **가장 가까운 클래스로 칠하고** 이미지 이름과 annotation id를 기록
2. GitHub Issue에 `labeling-question` 라벨로 스크린샷과 함께 등록
3. 결정되면 이 문서의 7장에 추가하고 버전을 올림 (v0.1, v0.2 ...)
