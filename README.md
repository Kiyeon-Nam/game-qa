# 딥러닝 세그멘테이션과 온톨로지를 결합한 게임 QA 자동 판정 시스템

경북대학교 2026-2 종합설계프로젝트2

### 추진 배경

- 게임 테스트는 자동화가 부족하여 수동 플레이테스트와 테스터 개인 역량에 크게 의존함
- 출시 후 가장 자주 수정되는 버그는 정보 전달 오류이며 UI 오류도 상위권으로, 화면에서 판별 가능한 버그의 비중이 큼
- 기존 자동화는 렌더링 글리치 탐지까지 발전했으나, 렌더링은 정상이면서 요소 간 관계가 틀린 의미 수준 버그는 판정하지 못하고 판정 근거도 제시하지 않음
- 엔진 내부 접근형 도구는 기능마다 테스트 스크립트 작성·유지가 필요하고 엔진에 종속되어, 소규모 개발팀이 부담 없이 사용할 도구가 부족함

### 목표 및 내용

- 사람이 플레이한 화면에서 의미 수준 버그를 자동 판정하고 위반 근거를 함께 제시하는 시스템을, 소규모 개발팀이 부담 없이 도입할 수 있는 형태로 개발
- 범위: 예상하지 못한 입력을 만드는 문제와 그 결과 화면을 판정하는 문제 중 판정(테스트 오라클)에 집중
    - 입력은 녹화 영상 또는 스크린샷, 판정 단위는 단일 화면
- 접근:검사할 상황을 열거하는 대신 화면 요소들이 항상 만족해야 하는 관계를 규칙으로 정의하고 위반을 검사하며, 개념과 규칙을 온톨로지로 구성
- 구성 요소
    - 게임 UI 온톨로지: 개념 계층·관계·규칙 정의. 사용자는 자기 게임 요소를 개념에 연결만 함
    - 세그멘테이션 모델: 화면을 공통 개념의 객체로 인식 (인스턴스 세그멘테이션)
    - AI 라벨링 도구: 모델 사전 라벨링으로 학습 데이터 구축 공수 절감
    - C++ 추론 라이브러리: Python 외 환경에서도 동일한 추론·후처리 제공 (기업 연계)
- 검증: 버그 주입 테스트셋으로 판정 정확도·근거 일치율 측정, 신규 게임 적용 시 온톨로지 규칙과 하드코딩 규칙의 수정량 비교

### 기대효과

- 규칙으로 정의된 의미 수준 버그를 녹화 영상에서 자동 판정해 QA 수동 확인 부담 감소
- 위반 규칙·대상 객체를 함께 제시하여, 오판이 인식 오류인지 규칙 문제인지 구분하고 수정할 수 있는 검토 가능한 판정
- 테스트 스크립트 작성·유지 없이 개념 매핑으로 도입하고 엔진에 종속되지 않아 소규모 팀의 도입·유지 부담 감소
- 세그멘테이션 추론 모듈을 C/C++ 라이브러리로 구성한 사례를 게임 화면이라는 새로운 분야에서 확보

## 판정 파이프라인

```
입력(플레이 녹화/스크린샷)
 → ① 프레임 추출
 → ② 세그멘테이션          training/, inferlib/
 → ③ 후처리·공간 관계 계산  inferlib/
 → ④ 그래프 변환           oracle/
 → ⑤ 규칙 검증             oracle/ + ontology/
 → ⑥ 리포트 생성           oracle/
```

구성 요소 사이에 주고받는 JSON 형식은 `schemas/`에 정의

## 폴더 구조

```
game-qa/
├── docs/               설계 문서
│   ├── ontology_v0.md                         온톨로지 v0: 버그 유형, 규칙, 개념 계층, 관계 정의
│   ├── labeling_guide_v0.md                   클래스 목록 v0, 라벨링 가이드
│   └── truelove2021_relational_bug_cases.csv  규칙 근거로 쓴 버그 사례 (Truelove et al., ICSE 2021)
├── ontology/           게임 UI 온톨로지: 개념, 관계, 규칙 정의
├── oracle/             판정기: 그래프 변환, 규칙 검증, 판정 리포트
├── training/           세그멘테이션 모델과 학습 파이프라인
├── labeling-tool/      AI 라벨링 도구
├── inferlib/           C++ 추론 라이브러리
│   ├── cpp/            C++ 구현
│   ├── python_ref/     후처리 Python 구현 (C++ 구현의 정답지)
│   └── bindings/       Python 바인딩
├── schemas/            구성 요소 간 JSON 형식
└── data/               데이터셋
    └── labels/         라벨 (COCO instance segmentation + relations)
```
